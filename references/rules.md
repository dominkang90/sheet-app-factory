# 지킬 규칙 (A.I.고 대시보드에서 얻은 것)

## 안전·개인정보
- 비밀번호(APP_PW)·API 키는 사용자가 앱스크립트 **스크립트 속성**이나 Vercel 환경변수에 직접 넣는다. 채팅에 붙여 달라고 하지 않고, 코드·커밋·공지·설명서에 쓰지 않는다.
- 단톡 안내문에는 주소만. "비밀번호는 대표에게 물어보세요".
- 회원 사진·실명은 로컬 미리보기에서만. 공개 페이지·홍보물에 넣지 않는다. 바깥용 그림이 필요하면 사람 없는 그림.
- 서버는 앱 폴더 밖의 드라이브 파일을 ID로 꺼내 주지 않는다(`inRoot_`). 새 파일 함수도 반드시 `fileById_` 를 거친다.
- GitHub 저장소는 비공개. `.gitignore` 에 `.env`, `*.local.json`.

## 코드
- **화면 스크립트에 슬래시+별표를 쓰지 않는다**(주석·글자 모두). 앱스크립트 HtmlService 가 거기서 스크립트를 잘라 로그인이 통째로 멈춘 적 있음. `'image/*'` 같은 파일 종류 글자도 해당 → `'image/*'`. build.py 가 검사하고 schema 글자는 자동으로 바꿔 준다.
- 칸은 순서가 아니라 **맨 위 제목**으로 찾는다. 칸 이름은 바꾸지 않는다(새 칸이 됨). 칸을 더하면 schema `version` 올리고 시트 백업 후 `처음_설정` 다시 실행.
- 날짜·시간은 글자로 저장한다(`'2026-11-26`). 시트가 시간대를 바꿔 하루 밀리는 일을 막는다.
- 여러 사람이 동시에 쓰는 곳은 `withLock_`.
- 서버 함수는 모두 첫 줄에서 `auth_(a)`. 권한은 화면과 서버 **둘 다** 확인한다(화면은 보기 좋게, 서버가 진짜 문지기).
- 덮어쓰기 패치(`fn = function(){ old(); … }`)를 계속 쌓지 않는다. 같은 기능은 한 파일 안에서 고친다(A.I.고는 30개가 넘게 쌓여 읽기 어려워졌다).

## 화면
- 성공 표시는 서버 대답 뒤에만(`saveBtn`). 기다리는 동안 버튼 안에 "저장 중…".
- 폰 폭 375px 기준. 글자 11px 이상, 누르는 곳 40px 이상(주요 버튼 44px).
- 색만으로 상태를 알리지 않는다(글자 같이). 확인 창 버튼은 "지우기 / 그대로 두기"처럼 동작 이름.
- 오래 걸리는 일은 0.6초 넘을 때만 아래쪽 작은 표시. 확인 창이 열리면 표시를 숨긴다.
- 자주 안 쓰는 버튼은 `details.fold` 로 접는다. 계산식 같은 설명도 접어서 "어떻게 계산해요?".
- 사진: 작은 그림 먼저, 6장씩 묶어 한 번에, 다음 사진 미리 받기, 크게 볼 때 흐린 그림→선명한 그림.
- 움직임은 `prefers-reduced-motion` 을 따른다.

## 배포
- 화면은 Vercel 한 곳. 앱스크립트는 데이터 처리만(doGet 은 상태 JSON).
- 배포 전 `build.py --mock && smoke.py` 전부 통과. 실패를 숨기고 배포하지 않는다.
- 웹앱 배포는 같은 배포 ID에 새 버전(주소 유지). 편집기에서 누가 고쳤으면 deploy.py 가 멈춘다 — 합친 뒤 다시.
- 배포 후 CHANGELOG.md 한 줄, git 커밋.
- 실제 폰 확인은 사용자(회원 2명). 모의 화면만 본 것은 "모의 화면에서만 확인"이라고 정확히 말한다.
